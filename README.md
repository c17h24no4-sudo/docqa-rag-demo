# docqa — вопросы по документам (RAG-демо)

Небольшой сервис: загружаешь документы (`.txt`, `.md`, `.pdf`, `.docx`), задаёшь вопрос обычным языком и получаешь ответ **со ссылкой на фрагмент и документ-источник**. Если ответа в документах нет, сервис так и говорит и ничего не выдумывает.

Стек: **FastAPI · PostgreSQL + pgvector · Docker · RAG · Claude API · pytest**.

> Учебный проект. Примеры документов в `sample_docs/` — условные, без реальных данных.

## Как это работает

```
файл → текст → куски по ~350 символов с нахлёстом → векторы (эмбеддинги)
                                                        │
вопрос → вектор → поиск ближайших кусков в PostgreSQL (pgvector) → топ-4
                                                        │
              куски + вопрос → Claude → ответ только по этим кускам, с номерами источников
```

- **Нарезка** (`app/chunking.py`): по абзацам и предложениям, с нахлёстом, чтобы смысл не рвался на границе.
- **Векторы** (`app/embeddings.py`): по умолчанию лёгкий хэш-эмбеддер без скачивания моделей (ищет по общим словам с нормализацией окончаний). Для поиска по смыслу есть `FastEmbedEmbedder` с многоязычной моделью (`pip install fastembed`).
- **Хранилище** (`app/store.py`): `PostgresStore` (pgvector, косинусная близость) и `MemoryStore` с тем же интерфейсом для тестов и запуска без базы.
- **Ответ** (`app/llm.py`): с ключом `ANTHROPIC_API_KEY` отвечает Claude строго по найденным фрагментам. Без ключа возвращает самое подходящее место из документа.

## Запуск в Docker

```bash
cp .env.example .env        # ключ Claude необязателен
docker compose up --build
```

Сервис: http://localhost:8000/docs (интерактивная документация).

```bash
# загрузить документ
curl -F "file=@sample_docs/dogovor-ustnyj-obrazec.md" http://localhost:8000/documents
# спросить
curl -X POST http://localhost:8000/ask -H "content-type: application/json" \
     -d '{"question": "В какой срок оплачивается остаток?"}'
```

## Запуск без Docker (в памяти)

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q
uvicorn app.main:app --reload
```

Без `DATABASE_URL` сервис хранит данные в памяти (после перезапуска пусто).

## API

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/documents` | загрузить файл, нарезать и сохранить |
| GET | `/documents` | список документов и число кусков |
| DELETE | `/documents/{id}` | удалить документ вместе с кусками |
| POST | `/ask` | вопрос → ответ + источники (документ, номер фрагмента, близость) |
| GET | `/health` | состояние, тип хранилища, режим ответа |

## Что проверено тестами (`pytest`)

Нарезка текста, поиск ближайших кусков, загрузка и вопросы через API, отказ на нерелевантный вопрос («В документах этого нет»), неподдерживаемые и пустые файлы, формирование запроса к Claude (без сети, через подменённый HTTP-клиент).

## Ограничения

- Хэш-эмбеддер ищет по словам, а не по смыслу; для настоящего семантического поиска используйте `FastEmbedEmbedder`.
- Нет авторизации и разделения документов по пользователям.
- Таблицы создаются при старте; миграций нет.
- Запрос к Claude проверен тестом без сети; живой вызов API нужен ключ.
